# Design review — NUR CRM (сектор Consulting)

Дата: 2026-09-04
Ревью: localhost:3000, живой dev-сервер, сектор `consulting`
Просмотрено: Лиды, Воронка продаж, Клиенты, Запросы клиентов, Продажи, Касса, Аналитика, Чаты (WhatsApp), Настройки — desktop (1470px) и mobile (390px)

## Итог

Продукт выглядит как настоящий рабочий B2B-инструмент, а не шаблонная AI-заготовка: один шрифт (Montserrat), сдержанная золотисто-чёрная палитра, узнаваемый паттерн навигации по разделам (карточка-иконка + заголовок + подзаголовок), метрики в аналитике с иконкой/значением/дельтой — всё это работает как единая система на большинстве экранов. Главные проблемы — не в стиле, а в местах, где система расходится сама с собой: страница «Настройки» выглядит так, будто её собирали отдельно от всего остального, стандартные кнопки систематически меньше 44px, а мобильная версия «Лидов» ломается из-за плавающей кнопки поверх контента.

**Design Score: B-** · **AI Slop Score: A-** (шаблонных AI-паттернов не обнаружено)

## Находки

### 1. Несогласованный дизайн страницы «Настройки» — высокий приоритет
`/crm/set`. Страница визуально живёт в другой системе, чем остальной CRM:
- Тёмный «hero»-блок с крупным белым заголовком — на всех остальных страницах заголовок на светлом фоне, без hero-блока.
- Вкладки «Моя компания / Безопасность / Интерфейс» — плоские текстовые табы в тёмной полосе с жёлтым подчёркиванием. Везде в остальном приложении для похожей навигации используется один и тот же паттерн: карточка с иконкой, заголовком и подписью (см. Лиды, Клиенты, Касса, Аналитика, Чаты).
- Заголовок секции «Основная информация» и подписи полей — блёклый серый цвет, выглядит как disabled-состояние, хотя поля, судя по всему, редактируемые.
- В каждом инпуте — иконка-галочка слева, без пояснения, что она означает (заполнено? проверено? сохранено?).

Это самая заметная проблема консистентности в продукте — пользователь, дошедший до настроек, попадает как будто в другое приложение.

### 2. Кнопки систематически меньше 44px — высокий приоритет
Стандартная высота кнопок в приложении — 40px («Изм.» 85×40, «Удалить» 115×40, «+ Лид» 44×40), иконки-действия в карточках лидов/клиентов — 36×34. Это ниже рекомендованного минимума touch-target (44×44) и особенно критично на мобильных экранах, где эти же элементы используются для тапа пальцем, а не клика мышью.

### 3. Плавающая кнопка перекрывает контент на мобильной версии — высокий приоритет
На 390px (мобильный вьюпорт) страница «Лиды»: внизу слева висит круглая жёлтая кнопка-гамбургер (☰), которая остаётся зафиксированной при скролле и наезжает на карточки лидов снизу. При этом гамбургер для меню уже есть в шапке — вторая кнопка того же назначения сбивает с толку. Плюс — в правом верхнем углу есть жёлтая круглая кнопка «+» создания лида: два одинаковых по цвету/форме круглых FAB с разными функциями конкурируют за внимание.

### 4. Ошибка валидации формы — модальное окно поверх модального окна — высокий приоритет
При создании лида (`+ Лид`) без заполнения полей и клике «Создать» поверх открытой формы появляется второе модальное окно: крупная красная иконка-предупреждение, заголовок «Ошибка», текст «Укажите имя или телефон лида», кнопка OK — в духе браузерного `alert()`. Пользователю не показывают, какое именно поле не заполнено (подсветка поля / текст под инпутом), а заставляют закрыть alert и догадываться. Двойное модальное окно — тяжёлый, резкий паттерн для тривиальной ошибки валидации.

### 5. Родные HTML date-инпуты рядом с кастомными компонентами — средний приоритет
На странице «Продажи» фильтр по датам — это два необработанных `<input type="date">` (дд.мм.гггг, системный календарь) прямо рядом с полностью кастомными пилюлями «Сегодня / Вчера / Неделя / Месяц». Выглядит как случайно забытый системный элемент в спроектированном интерфейсе.

### 6. Загрузка — только спиннер, без скелетонов, иногда с противоречивым текстом — средний приоритет
На Кассе, в списке чатов, в Продажах загрузка занимает 2–5 секунд и показывает только круг+«Загрузка…» на пустом фоне, форма скелетона не повторяет будущий контент. На странице «Продажи» одновременно показывались предупреждение «Справочник услуг пуст…» и текст «Загрузка…» под ним — два взаимоисключающих сообщения одновременно.

### 7. Перевёрнутая иерархия заголовков — средний приоритет
На странице «Запросы клиентов»: `h1` «Запросы клиентов» — 28px/800, а вложенный `h2` «Заявки» — 32px/700 (крупнее родителя), ещё один `h2` «Очередь заявок» — 18px/800. Семантическая и визуальная иерархия не совпадают.

## Что сделано хорошо

Единый шрифт по всему приложению, дисциплинированная золотисто-чёрная палитра без шаблонных фиолетовых AI-градиентов, переиспользуемый паттерн карточной навигации по разделам, видимый focus-ring на полях ввода, осмысленные пустые состояния (иллюстрация WhatsApp на пустом чате, понятная подсказка «Справочник услуг пуст»), метрики в Аналитике с корректной семантикой цвета (красный — для падения показателей).

## Быстрые победы (< 30 минут каждая)

1. Поднять высоту кнопок-действий до 44px (глобальный токен размера, не точечная правка).
2. Заменить `alert()`-подобную модалку валидации лида на инлайн-ошибку под полем «Имя».
3. Убрать/скрыть дублирующий плавающий гамбургер на мобильной версии Лидов либо убрать его при скролле.
4. Привести стили `<input type="date">` на странице Продаж к остальным контролам (либо заменить на кастомный date-picker).
5. Поменять местами размеры `h1`/`h2` на странице «Запросы клиентов».

## Что стоит сделать отдельным заходом

Пересобрать страницу «Настройки» под общий дизайн-язык приложения (карточная навигация вместо тёмных табов, единая типографика, убрать неочевидные галочки в полях) — это не 30-минутная правка, а отдельная задача.
