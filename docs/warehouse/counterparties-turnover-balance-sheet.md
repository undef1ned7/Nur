# Склад: оборотно-сальдовая ведомость по контрагентам (как в 1С)

**Статус:** фронт готов (считает сальдо сам как временную меру), ждёт правки на бэке.
**Страница:** `/crm/warehouse/counterparties` (вкладки «Клиент» / «Поставщик»).
**Дата:** 2026-09-23.

## 1. Задача

Таблица контрагентов — это оборотно-сальдовая ведомость за выбранный период
(по счёту 62 для клиентов, по 60 для поставщиков):

| Колонка              | Смысл                                                   | Для клиента (сч. 62)      |
| -------------------- | ------------------------------------------------------- | ------------------------- |
| Сальдо на начало, Дт | остаток долга **на утро** `date_from` в пользу компании | клиент нам должен         |
| Сальдо на начало, Кт | остаток в пользу контрагента                            | аванс / переплата клиента |
| Оборот, Дт           | движения за период, увеличивающие долг контрагента      | отгрузки (продажи)        |
| Оборот, Кт           | движения за период, уменьшающие долг контрагента        | оплаты + возвраты         |
| Сальдо на конец, Дт  | остаток **на вечер** `date_to` в пользу компании        | клиент нам должен         |
| Сальдо на конец, Кт  | остаток в пользу контрагента                            | переплата клиента         |

Главное правило: **сальдо — это остаток, а не сумма движений.** У одного
контрагента сальдо стоит только в одной колонке (Дт **или** Кт), вторая пустая.

```
нетто_начало = Σ(Дт-движения до date_from) − Σ(Кт-движения до date_from)
Сальдо на начало: нетто_начало > 0 → Дт = нетто_начало, Кт = 0
                  нетто_начало < 0 → Дт = 0, Кт = |нетто_начало|
Оборот Дт = Σ Дт-движений в [date_from; date_to]
Оборот Кт = Σ Кт-движений в [date_from; date_to]
нетто_конец = нетто_начало + Оборот Дт − Оборот Кт   (раскладывается по знаку так же)
```

### Что сейчас не так

В `analytics.debts.opening_debit` / `opening_credit` приходят **валовые суммы**:
все отгрузки и все оплаты до начала периода, а не остаток. Пример из прода
(«Мой контрпик»): `opening_debit = 41 454,93`, `opening_credit = 159 047,62`.
Обе стороны заполнены, и в каждой стоит сумма за всю историю. В 1С в этой
строке было бы Дт пусто, Кт = **117 592,69**. С `closing_*` то же самое.

Фронт пока выводит `opening_debit − opening_credit` и раскладывает по знаку
сам. От валовых или уже свёрнутых значений разница не меняется, поэтому
после правки бэка фронт менять не нужно.

## 2. Контракт API

### 2.1. `GET /api/warehouse/crud/counterparties/`

Параметры не меняются: `type`, `date_from`, `date_to`, `agent`, `search`,
`only_unpaid`, `page_size`. В каждом контрагенте в `analytics.debts`:

```json
{
  "opening_debit": "0.00",
  "opening_credit": "117592.69",
  "turnover_debit": "0.00",
  "turnover_credit": "0.00",
  "closing_debit": "0.00",
  "closing_credit": "117592.69"
}
```

- `opening_*`, `closing_*`: **свёрнутый** остаток. Как минимум одно из пары
  равно `0`.
- `turnover_*`: движения строго внутри `[date_from; date_to]` включительно.
  Движения до `date_from` сюда не попадают.
- Инвариант: `closing_debit − closing_credit == opening_debit − opening_credit + turnover_debit − turnover_credit`.
- Без `date_from`/`date_to` поведение прежнее: `turnover_*` не отдаются.
- `debt_total`, `paid_total`, `debt_remaining` фронт в ведомости больше
  **не использует**. Их можно оставить, если ими пользуется кто-то ещё.

### 2.2. Какие документы в какую сторону

**Клиент (`CLIENT`, `BOTH` на вкладке «Клиент»):**

| Документ                                        | Сторона |
| ----------------------------------------------- | ------- |
| `SALE` (проведён)                               | Дт      |
| `SALE_RETURN`                                   | Кт      |
| `MONEY_RECEIPT` (приход в кассу от контрагента) | Кт      |
| `MONEY_EXPENSE` (возврат денег клиенту)         | Дт      |

**Поставщик (`SUPPLIER`, `BOTH` на вкладке «Поставщик»), счёт 60.** Знак
зеркальный: поставка увеличивает наш долг.

| Документ                                      | Сторона |
| --------------------------------------------- | ------- |
| `MONEY_EXPENSE` (оплата поставщику)           | Дт      |
| `PURCHASE_RETURN`                             | Дт      |
| `PURCHASE` (проведён)                         | Кт      |
| `MONEY_RECEIPT` (возврат денег от поставщика) | Кт      |

Учитываются только проведённые документы (`POSTED`). Черновики и отказанные
(`DRAFT`, `REJECTED`) не учитываются. Дата движения берётся из `date`
документа (для денежных документов она теперь редактируется), а не из
`created_at`.

### 2.3. `GET /api/warehouse/counterparties/balance-summary/`

Карточки сверху страницы **больше не используют** этот эндпоинт. Фронт
показывает в них «Итого» таблицы: сумму каждой колонки по всем строкам,
без свёртки между контрагентами (развёрнутое сальдо, как строка `62.01`
в 1С). Если эндпоинт оставляете, его `opening/turnover/closing.debit|credit`
должны считаться так же: `opening.debit = Σ opening_debit` по контрагентам
и т. д. Нельзя сворачивать общую сумму в одно `net`.

## 3. Модель

Новых полей и моделей нет, меняется только расчёт `analytics.debts`.
Нетто на начало лучше считать одним агрегатом
`Sum(Case(When(date < date_from, then=signed_amount)))`, а не двумя
раздельными суммами.

## 4. Чек-лист приёмки

- [ ] У любого контрагента заполнено максимум одно из `opening_debit` и
      `opening_credit`, то же для `closing_*`.
- [ ] «Мой контрпик» за текущий месяц без движений: начало Кт = конец Кт =
      117 592,69, Дт пусто, оборот пустой.
- [ ] Инвариант из п. 2.1 выполняется для каждого контрагента.
- [ ] Движение, датированное днём `date_from`, попадает в оборот, а не в
      сальдо на начало. Движение, датированное `date_to`, тоже в обороте.
- [ ] Возврат товара клиентом (`SALE_RETURN`) уменьшает долг (Кт).
- [ ] Черновик и отказанный денежный документ ни на что не влияют.
- [ ] Период можно сдвинуть: сальдо на конец марта == сальдо на начало апреля.
- [ ] Вкладка «Поставщик»: поставка на 10 000 без оплаты → Кт 10 000 на конец.
