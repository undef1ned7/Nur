# Склад: подтверждение кассы — сделать выключаемым, по умолчанию выключено

**Статус:** фронт готов, ждёт реализации на бэке.
**Страница:** `/crm/warehouse/kassa` (сектор «Склад»), вкладки «Запросы» и
новая «Настройки».
**Дата:** 2026-09-16.
**Связано:** тот же принцип уже реализован для сектора Consulting —
[docs/consulting/backend-money-tenant/26-cash-confirmation-default-off.md](../consulting/backend-money-tenant/26-cash-confirmation-default-off.md)
(единый паттерн: company-level toggle, дефолт `off`, существующие компании
не трогаем).

## 1. Задача

Сейчас на складе **любой** документ (`SALE`, `PURCHASE` и т.д.), проведённый
с `payment_kind="cash"`, **всегда** уходит в статус `CASH_PENDING` и ждёт
решения во вкладке «Запросы» (`CashRequestsInbox`,
`POST /warehouse/documents/{id}/cash/approve|reject/` или
`POST /warehouse/cash/requests/{id}/approve|reject/`) — тумблера отключить
это нет вообще, поведение жёстко зашито.

Нужно то же, что уже сделали в Consulting: дать компании возможность
**выключить** обязательное подтверждение кассы, и **по умолчанию** оно
должно быть выключено — то есть наличные документы проводятся сразу
(`POSTED`), без очереди на подтверждение, пока компания сама не включит
этот режим в настройках.

## 2. Модель данных

Новая модель (или поле на существующей модели компании/склада — на
усмотрение бэка, лишь бы OneToOne с компанией):

```python
class WarehouseCashConfirmationSettings(models.Model):
    company = models.OneToOneField(Company, on_delete=models.CASCADE,
                                   related_name="warehouse_cash_confirmation")
    enabled = models.BooleanField(default=False)   # выключено по умолчанию
```

В отличие от Consulting (там три режима `required|cash_only|off`, потому
что различались способы оплаты), здесь и так `CASH_PENDING` создаётся
**только** для `payment_kind="cash"` — безнал проводится сразу и раньше.
Поэтому режим — простой boolean:

- `enabled=false` (**default**) — документы с `payment_kind="cash"`
  проводятся сразу в `POSTED`, `CASH_PENDING` не создаётся, никакого
  влияния на остальную логику (списание склада, зачисление денег и т.д.)
  не меняется, просто пропускается промежуточный статус.
- `enabled=true` — текущее (уже реализованное) поведение: `DRAFT →
  CASH_PENDING → POSTED`, ждёт `approve/reject` во вкладке «Запросы».

## 3. Точка применения

В обработчике `POST /warehouse/documents/{id}/post/` (там, где сейчас
безусловно ставится `CASH_PENDING` для `payment_kind="cash"`):

```python
def post_document(doc, *, user):
    ...
    if doc.payment_kind == "cash":
        settings = get_or_create_cash_confirmation_settings(doc.company)
        if settings.enabled:
            doc.status = "CASH_PENDING"
            create_cash_request(doc)
        else:
            doc.status = "POSTED"
            # сразу выполнить тот же side-effect, что при approve:
            # создание MONEY_* документа, зачисление в остаток кассы
            apply_cash_request_effects(doc)
    ...
```

Важно: логика начисления денег в остаток кассы (что сейчас происходит при
`cash/approve/`) должна выполняться **тем же кодом**, просто вызванным сразу
при `post`, а не отложенно при `approve` — чтобы не дублировать бизнес-
логику в двух местах.

## 4. Эндпоинты

```
GET   /warehouse/cash/confirmation-settings/
PATCH /warehouse/cash/confirmation-settings/   { "enabled": true|false }
```

```jsonc
// GET / PATCH-ответ
{ "enabled": false }
```

- `GET` для компании без сохранённой строки — отдаёт `{"enabled": false}`
  (виртуальный дефолт), не `404`.
- `PATCH` — только `owner`/`admin`. Остальным — `403`.
- Пока эндпоинта нет (`404/501`) — фронт показывает заглушку и работает как
  если бы `enabled=false` (см. §6).

## 5. Существующие компании — не трогаем

Как и в Consulting-решении: это смена **дефолта**, а не принудительная
миграция. Django-миграция должна только выставить `default=False` в модели
для новых строк; **не переписывать** уже существующие
`WarehouseCashConfirmationSettings` (если они где-то уже создавались явно —
что маловероятно, так как раньше настройки не было вообще, но проверить).

Поскольку раньше эта настройка **физически не существовала** — поведение
было безусловно «включено» для всех. Здесь, в отличие от Consulting, у нас
нет старых явных решений пользователей: до этого релиза *все* компании были
на `enabled=true` неявно (жёстко в коде). Формально это значит, что смена
дефолта на `false` для новых строк — это и есть поведенческое изменение для
всех существующих компаний склада, как только у них лениво создастся
настройка. **Это специально и осознанно** (сам запрос был «сделать
выключаемым, по умолчанию выключено»), но:

- Предупредите/уведомите компании, которые активно пользуются очередью
  подтверждения (есть история `approve/reject` за последние 30 дней) —
  им может быть неожиданно, что после релиза наличные проводятся сразу.
  Решение о рассылке уведомления — на усмотрение продукта, вне скоупа
  фронта.
- Альтернатива, если это слишком рискованно: завести
  `WarehouseCashConfirmationSettings(enabled=True)` строки миграцией
  **только для компаний, у которых были подтверждённые/отклонённые
  cash-запросы за всё время** (то есть они реально этим пользовались) —
  тогда для них ничего не меняется, а для всех остальных (кто ни разу не
  сталкивался с этой очередью) — новый дефолт `off`. Это решение продукта,
  не блокирует фронт-часть.

## 6. Фронт (уже сделано)

- `src/api/warehouse.js`: `getCashConfirmationSettings`,
  `updateCashConfirmationSettings`.
- `src/Components/Sectors/Warehouse/Kassa/WarehouseKassa.jsx`:
  - Новый компонент `CashConfirmationSettings` — чекбокс
    «Требовать подтверждение наличных операций», выключен по умолчанию;
    доступен только `owner` (вкладка «Настройки» скрыта для остальных ролей).
  - Вкладка **«Запросы»** скрывается из навигации, если `enabled=false` **и**
    нет ни одной заявки со статусом `PENDING` (если старые заявки остались
    от момента, когда режим был включён — вкладка не прячется, чтобы их не
    потерять из вида).
  - Пока эндпоинт не готов (`404/501`) — заглушка, работает как
    `enabled=false`.

## 7. Чек-лист приёмки

- [ ] Новая компания / компания без сохранённых настроек →
      `GET /warehouse/cash/confirmation-settings/` возвращает
      `{"enabled": false}`.
- [ ] При `enabled=false`: `POST .../post/` документа с `payment_kind=cash`
      сразу переводит его в `POSTED`, создаёт `MONEY_*` документ и
      зачисляет сумму в остаток кассы — без промежуточного `CASH_PENDING`.
- [ ] При `enabled=true`: поведение не изменилось — `CASH_PENDING`,
      `approve/reject` через инбокс, как сейчас в проде.
- [ ] `PATCH confirmation-settings/` доступен только `owner`/`admin` → `403`
      для остальных ролей.
- [ ] Безналичные документы (`payment_kind != "cash"`) не зависят от этой
      настройки вообще — проводятся сразу, как и раньше.
- [ ] Переключение `enabled` не трогает уже существующие документы в
      `CASH_PENDING` — они по-прежнему обрабатываются через
      `approve/reject`, только новые документы следуют новому режиму.
