# 24. Поле «Адрес» у лида

**Приоритет:** P2 — новое поле карточки, ничего не ломает, но фронт уже
отправляет его и ждёт, что бэк не отбросит и сохранит.
**Дата:** 12.09.2026
**Бэкенд:** `Lead` (`apps/consalting/models.py`), сериализатор `Lead`,
`POST /consalting/leads/`.
**Фронт (реализовано):**
`src/Components/Sectors/Consulting/Funnel/Funnel.jsx` (`LeadCreateForm`),
`src/Components/Sectors/Consulting/leads/modals/CreateLeadModal.jsx`,
`src/api/consultingLeads.js` (`ensureFunnelLeadForInbound`).

---

## 1. Задача

В обеих формах ручного создания лида («Новый лид» на доске воронки и «Новый
лид» на странице «Лиды» — это одна и та же операция с двух разных экранов,
см. комментарий в шапке `CreateLeadModal.jsx`: «Набор полей повторяет форму
создания лида на доске воронки») добавлено новое текстовое поле **«Адрес»**
рядом с «Email» / «Оценочная сумма».

---

## 2. Что нужно на бэке

### 2.1. Модель

```python
class Lead(models.Model):
    # …существующие поля…
    address = models.CharField(max_length=255, blank=True, default="")
```

Миграция — добавление колонки, `blank=True`/`default=""`, ничего не ломает
для существующих записей.

### 2.2. Сериализатор и API

`POST /consalting/leads/` — принять необязательное поле `address` (строка,
до 255 символов) в теле запроса, сохранить как есть (без валидации формата —
это свободный текст, не структурированный адрес с городом/индексом).

```jsonc
// Request (фрагмент, то, что реально шлёт фронт)
{
  "funnel": "uuid",
  "stage": "uuid|null",
  "title": "…",
  "full_name": "…",
  "phone": "…",
  "email": "…",
  "address": "г. Бишкек, ул. Киевская 95",
  "source": "…",
  "description": "…",
  "estimated_value": 0,
  "probability": 0
}
```

`GET /consalting/leads/`, `GET /consalting/leads/{id}/`,
`GET /consalting/funnels/{id}/board/` (карточки в `columns[].leads[]` /
`unassigned[]`) — отдавать `address` в ответе, как и остальные текстовые
поля лида (`full_name`, `phone`, `email`).

### 2.3. `PATCH /consalting/leads/{id}/`

Разрешить менять `address` наравне с остальными редактируемыми полями —
фронт пока не даёт править его после создания (см. §4), но если бэк уже
принимает произвольный набор полей через общий `PATCH`, отдельно исключать
`address` не нужно — просто не потерять его при частичном обновлении других
полей (стандартное поведение `PATCH`, не `PUT`).

### 2.4. `InboundLead`

**Не добавлять** `address` в `InboundLeadConsalting`/`POST
/consalting/inbound-leads/` — это поле есть только у `Lead` (карточка
воронки). Форма на странице «Лиды» (`CreateLeadModal.jsx`) создаёт
`InboundLead` через `createInboundLead()` (без адреса) и затем зеркальный
`Lead` через `ensureFunnelLeadForInbound()` — вот туда `address` и уходит.
Так что в `InboundLead` поле не нужно, только в `Lead`.

---

## 3. Что уже сделано на фронте

- `LeadCreateForm` (доска воронки, `Funnel.jsx`) — поле «Адрес», значение
  уходит в `payload.address` при `POST /consalting/leads/` (через
  `createLead` thunk).
- `CreateLeadModal` (страница «Лиды») — поле «Адрес», значение уходит в
  `overrides.address` → `ensureFunnelLeadForInbound()` → тот же `POST
  /consalting/leads/`, но с полями, собранными вручную во фронтовой
  «зеркальной» функции (см. [13-unify-leads-single-model.md
  §7](./13-unify-leads-single-model.md) про природу этого зеркала — временное
  решение до единой модели лида).
- Поле необязательное, пустая строка не блокирует создание лида.

---

## 4. Сознательно не в этой итерации

- **Отображение/редактирование `address` в уже существующей карточке лида**
  (детальный вид/модалка открытого лида на доске) — не добавлено. Сейчас
  адрес можно только задать при создании; посмотреть/поменять его потом —
  отдельная, более широкая задача (карточка лида показывает много полей,
  трогать её компоновку не входило в эту задачу).
- **Показ адреса в списке «Лиды» / карточках на доске** (кратким текстом
  под именем, как телефон) — не добавлено, только хранение и отправка при
  создании.
- **Структурированный адрес** (город/улица/дом отдельными полями, гео-код)
  — не требовалось, поле осталось свободным текстом.

---

## 5. Чек-лист приёмки

- [ ] `POST /consalting/leads/` с `address` в теле → лид создан,
      `GET /consalting/leads/{id}/` возвращает тот же `address`.
- [ ] `POST /consalting/leads/` **без** `address` (старые клиенты API,
      обратная совместимость) → лид создаётся как раньше, `address` = `""`.
- [ ] `address` виден в ответе `GET /consalting/funnels/{id}/board/` у
      карточек лидов (`columns[].leads[].address`, `unassigned[].address`).
- [ ] `PATCH /consalting/leads/{id}/ { "address": "…" }` обновляет поле, не
      затрагивая остальные.
- [ ] `InboundLeadConsalting` не получил новых полей — это осознанно (§2.4).
