## Общие соглашения (действуют во всех файлах)

### Формат

- **Все списки** — DRF-пагинация: `{ "count": int, "next": str|null, "previous": str|null, "results": [...] }`.
  Фронт всегда шлёт `page` и `page_size`; `page_size` может быть 20/50/100,
  ограничьте максимум сотней.
- **Поиск** — параметр `search` (icontains по перечисленным в каждом разделе
  полям). Фронт дебаунсит ввод, но запросы могут прилетать часто — держите
  индексы.
- **Период** — `date_from` / `date_to` в формате `YYYY-MM-DD`, границы
  **включительные**, по местному времени компании (Asia/Bishkek, UTC+6).
- **Сортировка** — `ordering` (DRF `OrderingFilter`), минус = по убыванию.
- **Деньги** — `Decimal(12,2)`, отдаются строкой или числом (фронт нормализует).
  **Проценты** — `Decimal(5,2)`, диапазон 0.00–100.00.
- **Мультитенантность** — каждая сущность принадлежит компании
  (`company = FK(Company)`); любой queryset обязан фильтроваться по компании
  текущего пользователя. Это относится и к вложенным объектам.
- **Enum-поля** отдавайте парой: машинное значение (`status`) и человекочитаемое
  (`status_display`). Фронт показывает `*_display`, если оно есть.
- **Списки значений в фильтре**: `status=new,assigned` — через запятую,
  разбирать как `__in`.

### Ошибки

```jsonc
// 400
{ "detail": "Понятное сообщение для менеджера", "field": ["ошибка по полю"] }
```

Фронт показывает `detail` пользователю дословно — пишите текст по-русски и
по делу («Сначала создайте клиента из лида», а не «Validation error»).

### Права

- `owner` / `admin` — видят и меняют всё по компании.
- Рядовой сотрудник — **только свои** записи (свои лиды, свои продажи, свои
  начисления, свои финансы). Это не UI-ограничение, а фильтр в queryset.
- Настройки (распределение лидов, схемы оплаты, правила премий, подтверждение
  кассы) — только `owner`/`admin`.

### Идемпотентность и транзакции

Любая операция, порождающая деньги (закрытие сделки, отмена, подтверждение
прихода), должна быть **атомарной** (`transaction.atomic`) и **идемпотентной**
(повтор не создаёт дубль). Ключ идемпотентности указан в каждом разделе.

### Реалтайм

Персональные события шлются **только адресату** через существующий WS-канал
(см. [../realtime-notifications.md](../realtime-notifications.md)). Список
событий — в конце каждого файла.

## Порядок реализации

Блоки **5 → 8 → 9** — единый денежный контур (продажа → касса → абонентка →
откат). Их нужно делать вместе и первыми: пока откат не работает, каждая новая
продажа и отмена добавляют расхождений в отчёты.

Далее: **1** (очередь лидов) → **4** (счётчики) → **3** (цепочка воронок) →
**2** (зарплата) → **7** (финансы сотрудника) → **6** (карточка и КПД).
