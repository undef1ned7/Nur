# Записи — количество одной услуги (процедуры)

**Сферы:** Услуги, Стоматология, Барбершоп.  
**Фронт:** `RecordaModal.jsx`, `RecordaUtils.js` (`expandServiceIds`, `setServiceQty`).

---

## 1. Задача

В процедурном кабинете (укол «Сайгандар» и т.п.) одну и ту же услугу нужно
добавлять **несколько раз** (4–10) в одной записи. Сумма и длительность
должны умножаться на количество.

---

## 2. Поведение на фронте

- Клик по услуге или **+** — добавляет ещё одну позицию (до **20** раз).
- Кнопки **×4**, **×6**, **×10** — быстро задать количество.
- В итоге: «8 поз. · … мин · … сом»; в списке/календаре: «Укол ×6».
- При сохранении в API уходит массив **с повторяющимися id**:

```json
{
  "services": ["uuid-укол", "uuid-укол", "uuid-укол", "uuid-укол"]
}
```

---

## 3. Контракт API (бэкенд)

### POST/PATCH `/barbershop/appointments/`

| Поле | Тип | Описание |
|---|---|---|
| `services` | `array` | Список id услуг; **дубликаты = количество** |

**Ответ** (рекомендуется для редактирования):

```json
{
  "services": [
    { "service_id": "…", "qty": 4, "name": "Укол Сайгандар" }
  ]
}
```

или плоский массив id с повторами — фронт поддерживает оба формата через
`expandServiceIds`.

### Расчёт `price`

- Если `price` передан с фронта — сохранять как есть (уже с учётом qty).
- Иначе: `sum(service.price × qty)` с учётом `discount`.

### Зарплата

При `completed` — начисление **на каждую позицию** (4 укола = 4 начисления
или 1 начисление × qty — на усмотрение бэка, см. `salary.md`).

---

## 4. Чек-лист

- [ ] `services` принимает дубликаты id, не схлопывает в один.
- [ ] GET appointment возвращает qty или повторы id.
- [ ] `services_public` / `services_names` отражают количество («×4»).
- [ ] Summary за день учитывает qty в сумме.
