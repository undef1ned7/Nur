# Товары-услуги (`kind: "service"`) — количество не ведётся

**Сферы:** Магазин, Услуги, Клиника (Стоматология), Барбершоп — все используют один и тот же справочник `/main/products/` и одну и ту же кассу.
**Фронт:** создание — `src/Components/Deposits/Sklad/AddProductPage.jsx` (+ `AddProductPage/utils/productUtils.js`), кассы — `src/Components/Sectors/Market/CashierPage/CashierPage.jsx` (`/crm/market/cashier`) и `src/Components/pages/Sell/Cashier/SellCashierPage.jsx` (`/crm/sell/start`).
**Статус:** ⚠️ Требуются правки на бэкенде.

---

## 1. Проблема

В карточке товара пользователь выбирает тип: **Товар / Услуга / Комплект** → в API это `kind: "product" | "service" | "bundle"`.

У услуги **нет остатка**: при создании количество не запрашивается и не вводится (стрижка, консультация, диагностика, доставка). Фронт отправляет `quantity: 0`, `stock: false`.

Из-за этого бэкенд отклоняет операции с услугой, применяя к ней проверки склада:

- при добавлении услуги в чек — ошибка вида «нет в наличии» / «недостаточно товара», потому что `quantity = 0`;
- услуга не проходит валидацию как товар без остатка.

**Ожидание:** у `kind = "service"` остаток не проверяется и не списывается **нигде** — услугу можно продать неограниченное число раз, независимо от `quantity`.

---

## 2. Что фронт присылает при создании услуги

`POST /main/products/create-manual/` (редактирование — `PATCH /main/products/{id}/`):

```json
{
  "name": "Стрижка модельная",
  "kind": "service",
  "barcode": "2000000000015",
  "alternate_barcodes": [],
  "brand_name": "",
  "category_name": "Услуги",
  "article": "",
  "unit": "шт",
  "is_weight": false,
  "price": "800",
  "wholesale_price": "0",
  "purchase_price": "0",
  "markup_percent": "0",
  "discount_percent": "0",
  "quantity": 0,
  "stock": false,
  "country": "",
  "expiration_date": null,
  "client": null,
  "plu": null,
  "hotkey_group": null,
  "description": "",
  "characteristics": null
}
```

Особенности услуги в payload:

| Поле | Значение | Почему |
|---|---|---|
| `kind` | `"service"` | тип записи |
| `quantity` | всегда `0` | количество у услуги не ведётся, поле в форме отсутствует |
| `stock` | всегда `false` | акционные ступени (`promotion_rules_input`) для услуг не отправляются |
| `purchase_price` | всегда `"0"` | себестоимости нет, поле в форме отсутствует |
| `is_weight` | `true`, если включена «Дробная услуга» | разрешает дробное количество в чеке (0.5 часа) |
| `packages_input` | **не отправляется** | поштучные упаковки к услугам не применяются |

**Требование к валидации создания/редактирования:** при `kind = "service"` поля `quantity` и `purchase_price` не обязательны; `quantity: 0` — валидное значение, а не «нет в наличии». Отсутствие `quantity` в теле запроса тоже должно приниматься (трактовать как `0`).

## 3. Обязательные правила для бэкенда

### 3.1. Продажа (POS)

Ни один из эндпоинтов ниже **не должен** проверять остаток и **не должен** списывать остаток, если `product.kind == "service"`:

| Метод | Эндпоинт | Тело |
|---|---|---|
| POST | `/main/pos/sales/{sale_id}/add-item/` | `{ "product_id": "<uuid>", "quantity": 1, "discount_total": 0 }` |
| POST | `/main/pos/sales/{sale_id}/scan/` | `{ "barcode": "2000000000015" }` |
| PATCH | `/main/pos/carts/{sale_id}/items/{product_id}/` | `{ "quantity": 3, "discount_total": 0 }` |
| POST | `/main/pos/sales/{sale_id}/checkout/` | оплата/закрытие чека |
| POST | `/main/pos/sales/{sale_id}/return/` | возврат услуги |

Конкретно:

1. **Добавление в чек.** `quantity = 0` у услуги не является причиной отказа. Ответ — `200/201` с созданной строкой чека.
2. **Любое количество.** Услугу можно продать `1`, `5`, `100` раз в одном чеке. Верхней границы, завязанной на остаток, нет. Для `is_weight = true` (дробная услуга) допустимо дробное количество (`0.5`, `1.25`).
3. **Закрытие чека не трогает остаток.** `quantity` услуги в справочнике остаётся `0` и не уходит в минус.
4. **Возврат не возвращает остаток.** Строка возврата с услугой создаётся, `quantity` товара не увеличивается.
5. **Сканирование.** Если у услуги задан штрихкод — `scan` находит её и добавляет в чек по тем же правилам.

### 3.2. Склад и отчёты

6. Услуги **не участвуют** в складских механиках: приход/поставка, инвентаризация, списание/брак, перемещение между складами, себестоимость (COGS), «Отрицательный остаток», «Общий остаток меньше минимального».
7. Пресеты фильтров склада (`GET /main/products/list/?preset=…`) не должны возвращать услуги в выборках, завязанных на остаток: `out_of_stock`, `negative_stock`, `stock_below_min`, `zero_cost`, `shelf_life_expired`, `shelf_life_expires_7d`.
8. В аналитике услуги учитываются **в выручке**, но не в остатках/оборачиваемости склада. Себестоимость услуги = `0`, маржа = цена продажи.

### 3.3. Список товаров

9. `GET /main/products/list/` возвращает услуги **всегда**, независимо от остатка — касса выводит их в общем списке товаров. Фильтр по типу уже используется фронтом: `?kind=service`, `?kind=product`, `?kind=bundle` (можно передавать несколько значений).
10. В ответе списка поле `kind` обязано присутствовать у каждой записи — по нему фронт решает, показывать остаток или подпись «Услуга».

### 3.4. Ошибки

11. Если услугу всё же нельзя добавить (например, закрыта смена) — возвращать `400` с понятным `detail`, но **не** формулировку про остаток.

---

## 4. Что уже сделано на фронте

- В списках товаров вместо количества у услуг выводится подпись **«Услуга»** (константа `SERVICE_STOCK_LABEL` в `src/tools/marketWarehouseFilters.js`, признак — `isMarketWarehouseServiceProduct`):
  - касса Магазина (сетка товаров, модалка горячих клавиш F1–F12);
  - касса Барбершопа / Услуг / Клиники (`/crm/sell/start`);
  - склад Магазина (таблица и карточки), старый склад Барбершопа/Услуг/Клиники (колонка «Количество» и статус);
  - подбор товаров в документах Магазина, подбор товаров в модуле «Бар».
- Клиентские проверки остатка для услуг отключены: услуга добавляется в чек и её количество меняется без ограничения по `quantity`.

Поэтому после правок на бэкенде отдельных изменений на фронте не потребуется.

---

## 5. Чек-лист приёмки

```
1. Создать услугу без количества  → POST /main/products/create-manual/ {kind:"service", quantity:0} → 201
2. Открыть смену, добавить услугу в чек → POST /main/pos/sales/{id}/add-item/ → 201 (без ошибки об остатке)
3. Поставить количество 5          → PATCH /main/pos/carts/{id}/items/{product_id}/ {quantity:5} → 200
4. Дробная услуга (is_weight=true), количество 0.5 → 200
5. Оплатить чек                    → POST /main/pos/sales/{id}/checkout/ → 200;
                                     GET /main/products/{id}/ → quantity по-прежнему 0 (не -5)
6. Оформить возврат услуги         → 200; quantity по-прежнему 0
7. GET /main/products/list/        → услуга в выдаче есть при любом остатке
8. GET /main/products/list/?preset=out_of_stock → услуги в выдаче нет
```
