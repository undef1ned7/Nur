# Маркет — Настройки кассы: код на удаление из корзины + максимальная скидка

**Экраны фронта:**
- Настройки: `/crm/set` → вкладка **«Касса»** (`src/Components/pages/Info/Settings/Settings.jsx`, вкладка добавляется в `src/Components/pages/Info/Tabs/Tabs.jsx`)
- Касса: `/crm/market/cashier` (`src/Components/Sectors/Market/CashierPage/CashierPage.jsx`)

**Новые эндпоинты (требуется реализовать):**
- `GET /main/pos/cashier-settings/` — прочитать настройки кассы компании
- `PATCH /main/pos/cashier-settings/` — сохранить настройки (только owner/admin)
- `POST /main/pos/cashier-settings/verify-delete-code/` — проверить код удаления

**Фронт-клиент:** `src/api/marketCashierSettings.js`, хук `src/hooks/useMarketCashierSettings.js`
**Статус:** фронт готов и задеплоен «мягко» — пока эндпоинтов нет, GET падает, фронт молча работает по старым правилам (код не спрашивается, лимита скидки нет). После реализации бэка обе функции включатся автоматически.

---

## 1. Задача

Владелец/админ магазина должен уметь:

1. **Задать код на удаление товара из корзины.** Если код задан — кассир перед удалением позиции (или корзины целиком) вводит код. Если код не задан (пустой) — удаление проходит как раньше, без подтверждения.
2. **Задать максимальный процент скидки.** Сотрудник (кассир) не может выставить скидку больше указанного процента — ни на строку, ни на весь чек. Пустое значение = без ограничения.

Важно: **существующее право `can_view_market_delete_cart_item` не трогаем.** Это отдельный, уже работающий механизм: он полностью запрещает удаление из корзины. Новый код — второй слой поверх него:

```
удаление разрешено, если:
  can_view_market_delete_cart_item (или роль owner/admin)      ← старое поведение, без изменений
  И (код не задан ИЛИ код введён верно ИЛИ роль owner/admin)   ← новое
```

## 2. Модель данных

Настройки — **одна запись на компанию** (singleton). Предлагаемая модель `MarketCashierSettings`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid | PK |
| `company` | FK → Company, `unique=True` | Компания-владелец настроек |
| `delete_item_code` | `CharField(max_length=8, blank=True, default="")` | Код на удаление из корзины. Пустая строка = код не требуется |
| `max_discount_percent` | `DecimalField(max_digits=5, decimal_places=2, null=True, blank=True)` | Максимальная скидка в %, `null` = без ограничения |
| `updated_at` | datetime | Авто |
| `updated_by` | FK → User, null | Кто последний менял |

Запись создаётся лениво: при первом `GET`/`PATCH` — `get_or_create(company=request.user.company)`.

### Совместимость со старым полем `Company.cashier_password`

В настройках компании (`/crm/set` → «Моя компания», только владелец) уже есть поле **«Пароль кассира для удаления из корзины»** — `Company.cashier_password`, сохраняется через `PATCH /users/settings/company/`. Оно до сих пор нигде в кассе не использовалось.

Требование: **сделать одно значение вместо двух.** Варианты (на выбор бэка, оба устраивают фронт):

- **Вариант A (рекомендуемый).** `delete_item_code` — это и есть `Company.cashier_password`: новый эндпоинт читает/пишет то же поле (либо новая модель, а `cashier_password` мигрируется в неё и превращается в property). Тогда старая вкладка «Моя компания» и новая вкладка «Касса» показывают одно и то же значение.
- **Вариант B.** Новое отдельное поле, а `Company.cashier_password` объявляется устаревшим (перестаём отдавать/принимать) — тогда сообщите, и фронт уберёт старое поле из вкладки «Моя компания».

⚠️ Пока вариант не выбран, фронт использует `company.cashier_password` как **fallback**: если `GET /main/pos/cashier-settings/` недоступен, а `cashier_password` в компании заполнен — код спрашивается и сверяется на клиенте. После реализации эндпоинта fallback не задействуется.

### Безопасность

Сейчас `GET /users/company/` отдаёт `cashier_password` **всем сотрудникам компании** — то есть кассир может вытащить код из ответа API (DevTools → Network). Это обесценивает всю затею.

Требования:
1. `delete_item_code` (и `cashier_password`, если оставляем) возвращать **только** пользователям с ролью `owner`/`admin`. Остальным — не включать поле в ответ вовсе.
2. Проверка кода — **только на сервере** (`verify-delete-code/`), клиенту код не нужен.
3. Код не логировать (ни в request-логах, ни в журнале удалений).
4. Желательно хранить хеш кода (`make_password`/`check_password`) и не возвращать сам код даже владельцу — вместо него флаг `delete_item_code_set: true`. Тогда владелец не «смотрит» код, а перезадаёт его. Фронт это поддерживает: если бэк не отдал `delete_item_code`, поле в настройках будет пустым, а факт «код задан» берётся из `delete_item_code_required`.

## 3. Контракт API

### 3.1 `GET /main/pos/cashier-settings/`

Доступ: любой авторизованный сотрудник компании (кассиру нужны `delete_item_code_required` и `max_discount_percent`).

**Ответ 200 — для owner/admin:**

```json
{
  "id": "0f0e6b4a-1f2b-4a2f-9f7a-9c9a3f11a1b2",
  "delete_item_code": "1234",
  "delete_item_code_required": true,
  "max_discount_percent": "10.00",
  "updated_at": "2026-07-31T12:04:11+06:00",
  "updated_by": "Иванов И."
}
```

**Ответ 200 — для кассира/остальных ролей (код не раскрываем):**

```json
{
  "delete_item_code_required": true,
  "max_discount_percent": "10.00"
}
```

Когда ничего не настроено:

```json
{
  "delete_item_code_required": false,
  "max_discount_percent": null
}
```

Поля:

| Поле | Тип | Кому | Описание |
|---|---|---|---|
| `delete_item_code` | string \| null | owner/admin | Текущий код. Не отдавать остальным ролям. Можно не отдавать вообще, если хранится хеш |
| `delete_item_code_required` | bool | всем | `true`, если код задан и непустой. Основной флаг для кассы |
| `max_discount_percent` | string(decimal) \| null | всем | Максимальная скидка в %, `null` = без ограничения |

Фронт также понимает алиас `delete_item_code_set` вместо `delete_item_code_required` (см. `normalizeMarketCashierSettings`), но каноничным считаем `delete_item_code_required`.

### 3.2 `PATCH /main/pos/cashier-settings/`

Доступ: **только `owner` и `admin`** своей компании. Остальным — `403`.

**Запрос (фронт отправляет оба поля сразу):**

```json
{
  "delete_item_code": "1234",
  "max_discount_percent": "10"
}
```

Сброс значений:

```json
{
  "delete_item_code": null,        // или ""  → код больше не требуется
  "max_discount_percent": null     // → ограничение скидки снято
}
```

**Валидация:**

| Поле | Правило | Ошибка |
|---|---|---|
| `delete_item_code` | только цифры, длина 4–8; `null`/`""` допустимы | `400 {"delete_item_code": ["Код должен состоять из 4–8 цифр"]}` |
| `max_discount_percent` | число `0 ≤ x ≤ 100`, до 2 знаков; `null` допустим | `400 {"max_discount_percent": ["Значение должно быть от 0 до 100"]}` |

**Ответ 200** — тот же объект, что и в `GET` (фронт синхронизирует форму по ответу).

### 3.3 `POST /main/pos/cashier-settings/verify-delete-code/`

Доступ: любой авторизованный сотрудник компании.

**Запрос:**

```json
{ "code": "1234" }
```

**Ответ 200:**

```json
{ "valid": true }
```

```json
{ "valid": false }
```

Требования:
- Отвечать `200` и в случае неверного кода (`valid: false`) — фронт показывает «Неверный код» в модалке и даёт повторить ввод. `400`/`403` фронт трактует как техническую ошибку («Не удалось проверить код»).
- Если код в компании **не задан** — возвращать `{"valid": true}` (нечего проверять).
- Сравнение — константное по времени (`check_password` / `secrets.compare_digest`).
- **Троттлинг обязателен:** не более ~10 попыток в минуту на пользователя (или на компанию). Код короткий, перебор тривиален. При превышении — `429`.
- Попытки (успешные и неуспешные) желательно писать в аудит: кто, когда, с какого устройства.

## 4. Серверная проверка (не только UI)

Фронт спрашивает код и режет скидку в интерфейсе, но это **не защита** — запросы можно отправить напрямую. Нужна проверка на бэке:

### 4.1 Удаление позиции из корзины

`DELETE /main/pos/carts/{cart_id}/items/{item_id}/`

Если у компании задан `delete_item_code` **и** роль пользователя не `owner`/`admin` — требовать подтверждение. Два варианта реализации (фронт готов поддержать любой, сейчас реализован первый):

- **Вариант 1 (текущий фронт).** Отдельный вызов `verify-delete-code/`, затем обычный `DELETE`. Бэк может проверять «была ли успешная верификация за последние N минут» по короткоживущему токену/сессии — если решите так, сообщите: фронт передаст токен.
- **Вариант 2 (надёжнее).** `DELETE` принимает код в заголовке `X-Delete-Code` (или в query `?code=1234`), без него/с неверным — `403` с `{"detail": "Неверный код удаления"}`. Скажите, если выбираете — фронт добавит заголовок в `deleteProductInCart`.

То же самое относится к удалению корзины целиком (`DELETE /main/pos/sales/{id}/` из кассы) — под кодом должно быть и оно.

### 4.2 Ограничение скидки

Проверять при:
- `PATCH /main/pos/carts/{cart_id}/items/{item_id}/` с полем `discount_total` (скидка на строку);
- `POST /main/pos/start/` (и любом другом месте, где приходят `order_discount_total` / `order_discount_percent`) — скидка на заказ.

Правило (для ролей **кроме** `owner`/`admin`, при заданном `max_discount_percent`):

```
скидка_на_строку   ≤ unit_price × quantity × max_discount_percent / 100
скидка_на_заказ    ≤ subtotal_чека        × max_discount_percent / 100
```

`order_discount_percent` дополнительно: `order_discount_percent ≤ max_discount_percent`.

При превышении — `400`:

```json
{ "detail": "Максимальная скидка — 10%", "max_discount_percent": "10.00" }
```

Фронт покажет текст из `detail`. Молча обрезать значение на сервере **не надо** — кассир должен видеть, что лимит сработал.

## 5. Поведение фронта (что уже сделано)

1. **Загрузка настроек.** Касса на маунте дергает `GET /main/pos/cashier-settings/`. Ошибка (404/403/сеть) = «функции выключены» + fallback на `company.cashier_password` для кода.
2. **Удаление.** Точки, где спрашивается код: кнопка «корзина» у позиции, уменьшение количества до нуля (кнопкой `−` и вводом `0` в поле), удаление корзины целиком. Всё это — **после** существующей проверки права `can_view_market_delete_cart_item` (её логика не менялась). Владелец и админ код не вводят.
3. **Модалка кода** — `DeleteCodeModal`: ввод, `Enter` — подтвердить, `Esc`/«Отмена» — отменить (позиция остаётся в корзине, количество восстанавливается). Неверный код — сообщение в модалке, ввод очищается, попытка повторяется. Пока открыта модалка, глобальные хоткеи кассы (F1–F12, Enter → оплата, сканер) отключены.
4. **Скидка.** При заданном `max_discount_percent` и роли не owner/admin:
   - в поле скидки строки подпись становится «Скидка (до 10%)»;
   - ввод больше лимита обрезается до лимита + предупреждение «Максимальная скидка — 10%. Установлено N сом»;
   - то же в модалке общей скидки (для режимов «Сумма» и «Процент»), в модалке выводится подсказка «Максимальная скидка: 10%».
5. **Настройки.** Вкладка «Касса» видна только при секторе «Магазин» и роли `owner`/`admin`. Поле кода — цифры, 4–8 знаков, кнопка «Убрать код» очищает значение; поле скидки — число 0–100 или пусто.
